# Repository Structure — Oneself Monorepo

The **Oneself Monorepo** organizes all applications, shared tooling, infrastructure templates, and architectural documentation into a single, cohesive Git repository powered by **Turborepo** and **pnpm workspaces**.

---

## ⚙️ Monorepo Tooling & Conventions

### 1. Workspace Configuration (`pnpm-workspace.yaml`)
```yaml
packages:
  - "apps/*"
  - "packages/*"

allowBuilds:
  bcrypt: true
  sharp: true
  unrs-resolver: true
  esbuild: true
```
All applications reside in `apps/*`. Native C++ dependencies (`bcrypt`, `sharp`) are pre-approved for deterministic pnpm builds.

### 2. Task Pipelines (`turbo.json`)
- **`dev`:** Concurrent execution of `apps/front`, `apps/dashboard`, and `apps/server` with non-blocking log streaming.
- **`build`:** Builds applications with output caching in `.next/**` and `dist/**`.
- **`lint`:** Parallel ESLint execution across all apps with turbo caching.
- **`typecheck`:** Non-emitting TypeScript typecheck (`tsc --noEmit`) across all applications.

### 3. Root Commands
- `pnpm dev`: Runs all 3 apps in parallel
- `pnpm dev:front`: Runs only storefront
- `pnpm dev:dashboard`: Runs only admin dashboard
- `pnpm dev:server`: Runs only backend API
- `pnpm build`: Builds all applications
- `pnpm lint`: Lints all applications
- `pnpm typecheck`: Typechecks all applications
- `pnpm format`: Formats monorepo with Prettier
